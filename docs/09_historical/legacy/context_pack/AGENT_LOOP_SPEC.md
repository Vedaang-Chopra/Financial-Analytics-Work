# Agent Loop Specification
# Claude Code = Architect + Planner (Brain)
# Pi Coding Agent = Executor (Hands)
# Verification = Claude Code or Pi reads test output and confirms

---

## The Core Loop

```
┌─────────────────────────────────────────────────────────────┐
│                    LOOP START                               │
│                                                             │
│  1. PLAN (Claude Code)                                      │
│     Read system state + task list                           │
│     Select next pending task                                │
│     Write MICROTASK_SPEC.md                                 │
│                          │                                  │
│                          ▼                                  │
│  2. EXECUTE (Pi Coding Agent)                               │
│     Read SMALL_MODEL_EXECUTION_GUIDE.md                     │
│     Read MICROTASK_SPEC.md ONLY                             │
│     Read only files listed in "Files to Read"               │
│     Make exactly the changes listed in "Exact Work"         │
│     Run the test command                                    │
│     Write EXECUTION_RESULT.md                               │
│                          │                                  │
│                          ▼                                  │
│  3. VERIFY (Claude Code or Pi)                              │
│     Read EXECUTION_RESULT.md                                │
│     Check: test count ≥ previous count?                     │
│     Check: all acceptance criteria met?                     │
│     Check: no regressions?                                  │
│                          │                                  │
│              ┌───────────┴──────────────┐                   │
│              ▼                          ▼                   │
│         PASS                        FAIL                    │
│         Mark task complete          Write AGENT_EXECUTION_  │
│         Update session_state.md     LOG.md entry           │
│         Write next MICROTASK_SPEC   Claude Code redesigns   │
│              │                      the task                │
│              └──────────────────────┘                       │
│                          │                                  │
│                    LOOP CONTINUES                           │
└─────────────────────────────────────────────────────────────┘
```

## Step 1: Claude Code Planning Session

### What Claude Code reads (mandatory, in order):
```
1. docs/agent_context/README.md
2. docs/agent_context/01_current_system_state.md   ← verified state
3. docs/agent_context/05_next_execution_roadmap.md ← forward plan
4. plans/TASKS_FULL_SYSTEM_MICRO_PLAN.md           ← find next pending task
5. plans/SMALL_MODEL_EXECUTION_GUIDE.md            ← understand Pi's constraints
```

### What Claude Code produces:
A single file `plans/MICROTASK_SPEC.md` (replace every iteration). Format:

```markdown
# MICROTASK_SPEC.md
# Task: TASK-G001
# Generated by: Claude Code
# Date: YYYY-MM-DD

## Task ID
TASK-G001

## One-Line Goal
Add validate_scheme_master_record() function to agent/validate.py.

## Context (2 sentences max)
The validate.py module has NAV and portfolio validators but is missing
scheme_master validation. This causes scheme_master records to bypass
quarantine even when required fields are empty.

## Files to Read (in order, no others)
1. `mutual_fund_ingestion/agent/validate.py` — existing validator pattern
2. `tests/test_agent.py` — existing validator test pattern
3. `docs/design/task_url_agent_design_pack/all_specs/09_validation_quarantine_and_provenance.md` — validation rules

## Files to Create or Modify
- `mutual_fund_ingestion/agent/validate.py` — add function
- `tests/test_agent.py` — add 2 tests

## Exact Work
1. In validate.py, add function validate_scheme_master_record(record: dict) -> tuple[bool, str]:
   - Return (False, "missing_scheme_name") if record.get("scheme_name") is empty
   - Return (False, "missing_isin") if record.get("isin") is empty
   - Return (True, "") otherwise
2. In runner.py, wire the new validator in the scheme_master parse path (same pattern as nav validator)
3. In test_agent.py, add:
   - test_validate_scheme_master_valid_record() — passes with complete record
   - test_validate_scheme_master_missing_scheme_name() — quarantines with correct reason code

## Acceptance Criteria
- validate_scheme_master_record exists and is importable
- Both new tests pass
- Full test suite passes (count ≥ 125)
- No modifications to profiling/ modules

## Test Command
./financial_env/bin/python -m pytest tests/test_agent.py -k "scheme_master" -v -q
./financial_env/bin/python -m pytest tests/ -q

## Do Not Do
- Do not touch profiling/ modules (frozen)
- Do not add a new file — modify existing validate.py only
- Do not implement Phase 2 logic
- Do not change the DB schema
```

## Step 2: Pi Coding Agent Execution Session

### Pi's mandatory read order:
```
1. plans/SMALL_MODEL_EXECUTION_GUIDE.md     ← rules (read all of it)
2. plans/MICROTASK_SPEC.md                  ← this task only
3. [files listed in "Files to Read" section only]
```

### Pi's constraints (enforced by SMALL_MODEL_EXECUTION_GUIDE.md):
- Read only the files listed in the task spec
- Modify only the files listed in the task spec
- Run only the test command listed in the task spec
- Do not implement anything not in "Exact Work"
- Do not read future phase specs

### What Pi produces:

## Step 3: Verification

### Claude Code reads EXECUTION_RESULT.md and checks:

| Check | Pass condition | Fail action |
|---|---|---|
| Test count | ≥ previous count | Log in AGENT_EXECUTION_LOG.md, redesign task |
| No regressions | 0 failures | Same |
| Acceptance criteria | All checked | Same |
| Files modified | Only listed files | Revert unexpected changes |
| Exact work done | Matches spec | Add clarification to next spec |

### If PASS:
1. Update `plans/TASKS_FULL_SYSTEM_MICRO_PLAN.md` — mark TASK-G001 as `Status: complete`
2. Update `docs/agent_context/01_current_system_state.md` — update test count and status
3. Update `docs/session_state.md` — write current handoff using template
4. Generate next `plans/MICROTASK_SPEC.md` for the next pending task

### If FAIL:
1. Write entry in `docs/ai_context/AGENT_EXECUTION_LOG.md`
2. Identify root cause (wrong file path? missing dependency? ambiguous spec?)
3. Rewrite `plans/MICROTASK_SPEC.md` with the fix applied
4. Note the DO NOT REPEAT in the next spec

## What Claude Code Decides (Not Pi)

- Which task to do next
- Whether a test failure is a blocker or a known gap
- Whether to skip a task (with documented reason)
- Whether Phase 2 gate is met
- Architecture or design changes
- Whether to add a new task to the micro plan
- When to update CODEBASE_MAP.md

## What Pi Decides (Not Claude Code)

- How to implement "Exact Work" within the constraints given
- Which specific lines to write
- Which test assertion style to use
- When to ask for clarification (write in EXECUTION_RESULT.md as a blocker)

## What Neither Decides Without Human Approval

- Changing the DB schema beyond what is spec'd
- Adding new CLI subcommands
- Modifying Phase 1A/1B frozen modules
- Starting Phase 2 before the gate criteria are met
- Changing the strategy hierarchy (static → network → playwright → vlm → manual)
